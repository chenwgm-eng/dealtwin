# B2B 销售数字孪生系统 (Sales Digital Twin) - 系统规格说明书

## 1. 产品愿景与定位

打造一个基于《挑战者销售》（Challenger Sale）理论的 **B2B 打单领航员与推演沙盘**。系统将代表客户侧干系人的大语言模型转化为具备内部政治博弈与社交动态的智能体（Agents）。

### 1.1 针对的核心业务痛点

本系统致力于解决一线 B2B 销售最致命的三个执行痛点：

1. **盲人摸象（找不对人）**：多数销售无法准确定义和识别客户的真实决策流程、关键干系人，难以画出清晰的决策权力/利益影响图。系统不仅能记录，更能**主动推断并预警**图谱盲区。
2. **无的放矢（开不好会）**：即便找到了关键人，也不知道该说什么，面对多方参与的复杂汇报会更是缺乏预判，往往沦为无效客套或被多方质疑问死。
3. **刻舟求剑（不更状态）**：客户内部状态是动态变化的，但多数销售几乎不会动态更新和校准决策流程上所有人的状态。系统提供**无感自然语言录入**与透明的流转日志，消灭“填表式”的反人类操作。

### 1.2 系统核心交付价值 (AI 领航输出)

针对上述痛点，系统在每个销售阶段明确回答用户三个终极问题：

1. **接下去要做什么？（Next Best Action）**：系统自动探测并提示图谱盲区，动态规划下一步推进动作。
2. **每次拜访/会议的关键是什么？（Meeting Strategy & Simulation）**：针对单人拜访，提供**一键生成的静态阅读简报**；针对多人汇报会，支持**直接上传数十页 PDF 材料**进行“虚拟群辩推演”，输出《会前准备与攻防手册》，指导材料完善与现场问答应对。
3. **怎么推进项目顺利 Close？（Closing Path）**：推演客户内部闭门会议，测算赢单率，指出达成共识的最短联结路径，并通过清晰的系统日志（朋友圈式时间轴）解释状态变更原因，建立人机信任。

## 2. 技术栈架构 (基于多智能体群体预测引擎)

* **前端**：Vue 3 + Vite + Vue Router（单页面工作流），D3.js / G6（动态干系人权力图谱可视化，支持红黄绿支持度热力渲染及状态时间轴）。
* **后端**：Python + FastAPI（API 服务蓝图，支持异步多 Agent 流式交互与并发推演）。
* **数据库**：SQLite + SQLAlchemy（持久化基础业务数据），引入 NetworkX 用于复杂图谱关系权重计算。
* **AI 与多智能体引擎**：
  * **文档解析引擎 (Doc-Parser)**：引入 LlamaParse 或 Unstructured.io，专门用于高精度解析长篇 PDF（抽取表格、提取核心论点、保留排版结构），避免信息丢失。
  * **Zep / GraphRAG**：用于构建和检索客户干系人知识图谱、长短期记忆，以及承接文档解析后的结构化片段。
  * **OASIS**：核心多智能体社交引擎，承载干系人智能体，模拟客户内部的互动、群辩会议发酵。
  * **LangChain (ReACT)**：用于报告生成、策略顾问、待办任务生成与日常反馈文本无感解析。

## 3. 核心实体与数据模型设计 (Database Schema)

### 3.1 `Project` (项目与客户背景表)
包含项目的基本信息以及客户公司概况及战略措施，作为推演的“大背景指引”。
* **基本信息**：项目名称、当前销售阶段、预算规模。
* **公司概况 (Company Context)**：所属行业、公司愿景/战略目标。
* **业务痛点 (Status Quo)**：客户当前的业务挑战与财务状况。

### 3.2 `Stakeholder` (干系人/智能体节点表)
代表客户方的具体人员（权力图谱中的 Node）。
* **基础信息**：姓名、职位、职级、职责范围。
* **个人私利 (Personal Agenda)**：保住职位、减少工作量、个人晋升。这是推演干系人真实动机的核心。
* **买方角色 (Buyer Profile)**：Mobilizers（行动派/导师/怀疑论者）与 Blockers（反对者/向导/闲聊者）。
* **结构化数值属性 (0-10分)**：`Decision_Power` (决策影响力)、`Support_Level` (支持度)、`Urgency` (紧迫感)。

### 3.3 `Relationship` (关系连线表 - 图谱推演核心)
定义图谱节点之间的连线 (Edges)，决定信息在沙盘发酵中能否成功传递。
* **Source_ID & Target_ID**：关联两个干系人。
* **关系类型**：直接汇报、平级协作、私交联盟(Allies)、利益冲突(Conflict)。
* **影响力权重**：量化A对B的游说成功率。

### 3.4 `MeetingSimulation` (多人会议推演记录表)
承载重要会议的战前推演记录：
* **Input_PDFs**：关联销售直接上传的数十页 PDF 计划书、方案、报价单等。
* **Participants**：本次会议涉及的图谱干系人列表。
* **Simulation_Result**：关联生成的《会前准备与攻防手册》。

### 3.5 `OpportunityTask` (商机推进任务表)
基于推演结果自动生成的待办任务（TODOs）：
* **任务类型**：探测图谱盲区、打消顾虑、建立结盟、提供定向材料等。
* **单点拜访简报 (Action Brief)**：一键生成的静态阅读简报内容记录。

### 3.6 `StateChangeLog` (AI 状态变更追踪日志表)
解决“黑盒”问题，保证系统所有的状态变化有迹可循：
* **变更对象与数值**：例如 `CTO Support_Level: 4 -> 7`。
* **AI 归因解释 (Reasoning)**：如“沙盘推演中，CTO 听取了业务线关于 ROI 的汇报，由于利益一致，支持度被动上升”。

## 4. 智能体与模型协作机制

### 4.1 会前：虚拟会议室推演 (长篇 PDF 解析与群辩)
当销售需要面对多人评标/方案汇报时，直接将 **几十页的 PDF 方案** 丢入系统触发此引擎：
* **深度文档解析 (Layout-Aware Parsing)**：专门的解析引擎将 PDF 拆解为技术架构、商业收益、项目报价等结构块，并建立向量索引。
* **各取所需读取规则**：不同干系人 Agent 基于其背景“带着滤镜看材料”。（例如：CFO Agent 自动跳过技术架构，直接扫描成本与 ROI 部分；业务 VP Agent 聚焦效能提升案例）。
* **沙盘群辩模拟 (Group Debate)**：Agents 在虚拟会议室中针对材料互动，互相诘问。
* **输出：《会前准备与攻防手册》**：
  1. **材料完善建议**：“第15页的 ROI 计算缺乏实施成本项，CFO 会在此发难，建议补充。”
  2. **高频问题预判与应对 (Q&A)**：“CTO 会问：系统平滑迁移需要多久？应对策略：调用案例 A，强调 48 小时无感切换。”
  3. **会场走向预演**：“若采购部纠缠价格，切勿直接让步，应将话题抛给业务部 VP（属于我方支持者），让他强调业务痛点的紧迫性。”

### 4.2 会后：Feedback Parser 与无感闭门发酵规则
降低销售录入负担，自动推演客户内部的“二次沟通”：
* **非结构化随录录入**：销售在车上语音输入或粘贴一段杂乱备忘录：“今天见 CTO 聊了降本，他同意了但怕系统崩溃。” Parser Agent 自动更新属性并写入 `StateChangeLog`。
* **OASIS 闭门发酵 (Post-Meeting Simulation)**：
  * *Mobilizers（行动派）规则*：支持度 > 6 的行动派，会基于 `Relationship` 连线自动模拟其向上级汇报、推销方案的过程，进而推演上级状态的被动变化。
  * *Blockers（反对者）规则*：支持度 < 0 的人，系统推演其在背后寻找 Allies（盟友）散播负面顾虑的过程，计算负面情绪在组织内的“传染半径”。

### 4.3 Strategy Agent (策略顾问大脑)
* **主动盲区预警**：实时扫描图谱完整性，主动告警（例如：“当前缺失财务决策者的信息，极易在最后环节被一票否决”）。
* **生成 Next Best Action**：基于图谱热力值计算，自动刷新下一步核心待办任务列表。
* **一键静态简报**：为单人拜访一键生成包含“痛点陈述 -> 破坏固有认知 -> 引入方案”的结构化挑战式销售话术。

## 5. 前端工作流与交互形态

* **步骤 1：立项与全景扫描**：上传招投标文档或客户主页，系统生成带有“未知身份虚线框”的图谱，指引销售补全缺失角色。
* **步骤 2：图谱微调与单点突破**：拖拽节点调整权力和支持度。点击任意节点，一键获取“单点突破静态拜访简报（Action Brief）”直接供销售阅读。
* **步骤 3：多人会议决战沙盘**：
  * 开辟专门的“作战室”面板。
  * 销售拖入参会的干系人节点，**一键上传完整的 PDF 汇报材料**。
  * 进度条结束后，系统输出结构化的《会前准备与攻防手册》。
* **步骤 4：无感更新与状态追溯**：
  * 提供一个简单的文本框/语音入口供销售随时丢入杂乱纪要。
  * 右侧或底部悬浮常驻 **“朋友圈式状态流转时间轴”**，以时间线流形式展示 AI 每次更新数据的理由。
  * 看板中心常驻展示当前赢单率预测与下一步行动推荐卡片。
